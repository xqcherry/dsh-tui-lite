# dsh TUI 客户端架构重构计划

目标：在现有代码上收敛为以插件形式接入 dsh 的完整终端客户端；用户安装一个 npm 包后可直接运行 dsh-tui，内核作为固定版本运行依赖随包安装。

## 已确认的边界

- dsh 负责 agent、模型、工具执行、持久化与策略；客户端负责展示投影和交互。
- 插件装配连接 dsh-adapter、app、tui；终端渲染器保留，不重写。
- 官方包只在 dsh-adapter 导入；app 不依赖适配实现或界面；tui 不直接调用适配实现。
- 删除多后端框架、native.dsh 绕行、无用类型和打包声明；按职责拆分巨型客户端接口。
- 使用随包内核和当前安装的 TUI，不依赖全局 dsh、pnpm，不启动时下载第二份 TUI。
- 升级通过 npm；删除双副本启动、自更新、更新重启和救援 profile。
- 持久化 transcript 是事实来源；保留顺序、锚点、tool call ID 和会话切换隔离。
- 保留核心聊天、审批问答、会话管理、配置及现有用户数据格式。

## 实施步骤

1. 建立构建与回归基线，保留已有开发规范，在独立功能分支工作。
2. 固定内核运行依赖，收敛单份 profile 启动链路并验证打包安装。
3. 分离客户端状态/契约、界面和上游接入，增加依赖边界检查。
4. 删除多后端与重复路径，迁移设置/消息/会话逻辑并保持行为验证。
5. 清理依赖及文档，完成 build、专项、verify、窄 TTY 和实际打包验证。
