# 功能模块重构实施记录

目标：单 npm 包、功能目录优先，允许重写内部接口，保留现有功能、命令、用户数据和持久化语义。

## 已实施的第一批

- 建立 composer、transcript、sessions、settings、decisions、activity、workbench 七个模块，各有运行时入口与类型契约。
- 将基础协议、平台能力、公共 UI 和终端门面分开，迁移原 app/tui/utils 实现。
- 工作台通过输入、会话、设置、消息和页面服务的分域端口协作，业务模块不再导入全量 Client。
- 输入拆成草稿规则、图片 token、几何计算、撤销、图片所有权、历史、提交、附件、键盘和布局；消息列表拆出行渲染及签名计算。
- 服务商向导拆成添加、编辑、认证、发现、提问和配置组装。
- 增加公开入口、模型纯度、模块无环、平台叶子依赖和官方导入隔离检查。
- 验证器改为串行，降低同时运行渲染与图片测试的资源峰值。

## 验证要求

- 每批代码修改通过 `pnpm build`、相关专项及 `pnpm verify`，终端行为在窄 TTY 检查。
- 拒绝提交保留草稿、历史与附件；异步图片、排队和撤回不得串会话或重复发送。
- 回放与实时投影沿用现有 golden，不因文件迁移修改预期。
- 会话切换保留回滚、generation、占用账本与恰好一次释放。
- 最终需要实际打包安装，不用源码验证代替包内运行验证。
