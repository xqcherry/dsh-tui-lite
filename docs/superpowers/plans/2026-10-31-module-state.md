# 模块状态与运行时编排

本阶段承接功能目录迁移，目标是删除聚合的 `Client`、`ClientState` 和全局版本订阅，让模块拥有状态，adapter 只连接宿主资源与模块入口。保留一个 npm 包，不改写终端渲染器。

## 状态归属

| 模块 | 拥有的数据 |
| --- | --- |
| sessions | 会话身份、generation、工作目录、标题、颜色、运行状态、模式、权限 preset |
| settings | 模型、服务商、推理强度、上下文窗口、显示偏好 |
| composer | 选择、待发 FIFO、取消状态、附件入口；草稿仍由输入控制器管理 |
| transcript | 消息行、历史窗口、用量、费用、TPS、目标、待办、上下文投影 |
| activity | 后台任务和子代理归约、列表、子代理费用 |
| workbench | 通知、命令列表与界面协调 |
| decisions | 已独立的问题和审批队列，保留原有队列语义 |

## 实施次序与验收

1. 建立稳定、不可变快照和共享发布协调器。批量操作先提交所有模块快照，再通知订阅者；流式更新立即可读，通知约 16 ms 合并。保留二进制图片和其他不透明对象的语义。
2. 迁移 sessions/settings 的状态和持久化元数据处理。保持原有事件去重方式，不添加全局 seq 去重。
3. 迁移 composer/transcript/workbench；界面获取模块快照和命令，不再订阅聚合版本。测试中的旧原始对象可由测试专用 fixture 适配，生产代码不保留平面兼容桥。
4. 迁移 activity 的纯归约，官方宿主读写仍在 adapter。任务投影通过 transcript 入口分配行身份，不持有可写消息数组。
5. 保持 prepare/adopt/abandon 事务：提交前失败保留旧绑定；提交后失败撤销新绑定并报错；会话重置先同步相关模块再通知。
6. 删除旧运行时状态与过渡接口，更新架构文档，检查边界、构建、专项回归、完整回归、窄 TTY 和实际打包安装。

## 实施约束

- `store.getSnapshot()` 对订阅者暴露已提交快照，引用在无变化时稳定。
- 模块 ingress 只供运行时使用；`read()` 返回当前写入状态的不可变投影，`patch/update` 是写入入口。
- 各模块保留私有可变归约数据，不把 writer 或底层消息行交给 UI。
- 持久化 transcript 是事实来源；保持事件顺序、序列锚点、tool call ID、绑定 generation、输入 FIFO 与释放次序。
- 所有构建和测试由主任务串行执行，以 nice 19 固定到一个可用 CPU，限制原生工作线程。独立代码任务不启动测试或编译。
- 本阶段完成与否以最终验证记录为准；计划文件不表示验收已通过。
